# M4：旅级协作、通信与情报

规则版本为 `m4-coordination-1`。沿用全局 Maven 3.9.9、JDK 25；运行与认证方式见 README。

## 浏览器操作

1. 在「部署战场」载入「渡河协作」，冻结并启动实验，进入「推演指挥」。
2. 选择蓝方，打开「协作」，点击「载入渡河任务」。SVG 显示 `bridge → cross`。
3. 选择任务可修改前置命令 ID 和失败分支；战区输入矩形边界。点击「更新协作」，提交并锁定蓝方；红方提交空命令并锁定。
4. 结算后，工兵在河边架桥，装甲收到成功确认后渡河，到达 `(4,0)`。点击 DAG 节点过滤相关日志；悬停显示完整依赖与确认结果。
5. 「观察」可选本方师部或全知验证。「通信」显示连线。师部视图中的位置、HP、设施和日志来自服务端知识投影，地图标注报告日期；连线仅按最后已知节点推定，不承诺当前仍连通。
6. 从同一冻结版本创建相同种子的实验，在协作表单改为「无旅部调度对照」，保留同样任务。独立启动延迟由种子、日期、团 ID 和当地地形确定，可能自然保序，也可能渡河任务先遇到断桥。

部署面板新增「通信」标签，可在选中格保存／移除固定工事，设置 HP 和全场半径。缺省半径为 5，允许 1–8；旧场景无需增加字段。炮兵可选择「攻击通信工事」并点击敌方设施格。

## 执行规则

每方每天最多一个 `OperationPlan`，包含一个战区、最多 16 个节点。节点引用同方已提交的团级命令，一个团仍只接受一条日命令。服务端校验环、缺失依赖、重复任务、旅属、战区范围及两个存活通信连。休整在日末结算，不能作为日内协作节点。

- `COORDINATED`：命令由连通师部的旅部向可达部属送达。送达与启动分开；收到但等待依赖的任务不会因旅部随后失联而丢失。未收到任务继续等待。
- 前置结果分别记录物理事实 `fact`、本团已收到的 `confirmed`、`received` 和节点状态。只有完成时本地目击，或通过仍有效的旅通信链收到源团结果，才能确认；后台事实变化本身不能解锁任务。已经错过的远方事件不会因后来走近而自动成为目击记录。
- 失败分支为 `HOLD`（原地等待）、`CANCEL`（取消）或 `CONTINUE`（执行本节点既定行动作为备用行动）。无法确认前置失败时仍等待确认，不读取隐藏失败事实。
- `INDEPENDENT`：各任务已事先交付，按 0–24 整数时间单位的可复现环境延迟独立启动，不保证依赖顺序。移动耗时仍遵守最慢有效连速度。
- 未纳入协作计划的普通命令沿用 M2/M3 的「事先下达的团级命令」语义。这是实验对照输入；实时通信送达约束应用于旅级计划。
- 任务与路线仍以天为作用域。达到迭代上限后，未完成任务记录等待／待续，次日由玩家重新下令，不隐式自动重发旧计划。

架桥耗时 15。工兵必须在待修河边两端各一格以内；目标格是该河边的一个端点，因此工兵可以在侧面施工而不堵住渡河单位。地图按规范化格边顺序选择匹配河边。桥梁物理状态更新后，重新安排的移动才使用新通行条件。

炮击准备的完成表示本团执行了火力任务，不保证摧毁目标。执行前炮兵被歼灭会产生前置失败，合法目击者可选择备用分支。远方实际命中与本团射击完成分开；未知目标处的落空日志不直接进入本团知识。

攻击通信工事耗时 15，普通有效连射程 1，有炮兵时射程 3；伤害为有效连 `max(1, soft × hp / maxHp)` 之和，仅减少设施 HP。设施 HP 归零立即停止中继。设施不具备组织度。

## 通信与报告

有效通信连和 HP 大于零的固定工事是中继节点，同阵营半径内连接。普通团是收发终端，不可充当中继。旅部协调需要两个存活通信连，师部接收需要至少一个。

`IntelligenceState` 分别保存团、旅、师的不可变 `Knowledge`，以及待送达 `Report`。本地观察半径为 1；初始本方部署、己方通信工事和勘测格边合法已知，敌军仅通过本地观察获知。地形为公开地理信息。接敌、移动、设施行动后收集观察；位置、HP、桥梁与工事记录日期和日内时间，避免较早观察覆盖较晚事实。歼灭必须有本地死亡事件目击，不能凭全局名册消失推断。

第 N 天本地补给观察可供当日学说使用。日结算同时完成进入 N+1 的边界：当网络连通时，N 日报告送达师部，并在这个边界共享给连通部队，不再等待 N+2。失联报告留在本地队列，恢复连接时补送；已被歼灭的报告源不能事后上传。团级撤退规划只使用已知补给和已知格边；物理移动仍由真实地形约束。

日 N 的 JSONL 尾部包含 `ReportDelivery / REPORT_DELIVERED`，其 `day=N+1`、`observedDay` 和 `deliveredDay` 明确表达边界时间；ID 使用独立 `dN-report-*` 前缀。这不是第 N 天提前获取共享情报。

## API 与重放

- `GET /api/v1/presets/coordination`：实验场景。
- `PUT /api/v1/games/{id}/orders/{side}`：原提交结构新增可选 `operation`，与命令共享版本检查、锁定及幂等语义。
- `GET /api/v1/games/{id}/view?perspective=DIVISION&side=BLUE`：师部已知投影；`OMNISCIENT` 为验证观察。GET 不更新世界、知识或日志。
- 日运行清单包含双方计划、种子、规则版本、完整输入团记忆和分层情报。次日 `inputHash` 等于上日 `stateHash`，可使用上日 world 和清单独立重放。

现有 `/turn` 和日归档保留全知调试数据；投影用于实验观察隔离，不是多人权限系统。师部 UI 不使用全知响应补齐缺失单位、战损、补给或任务结果。历史全知结果可导出；师部模式只显示当前已送达报告，历史回放留给 M5。

OpenAPI 从 Java 端点／record 生成，不维护静态规范。默认半径、无通信工事的旧输入保留 `canonical-v1` 场景指纹；新通信字段使用该编码的 `communication-v1` 扩展段。M4 的运行状态指纹包含分层知识及滞留报告，历史黄金摘要保留，新摘要另存 `scenarios/m4-*-expected.json`。

验证命令：

```sh
mvn -o -B -ntp spotless:apply clean verify
python3 scripts/smoke-test.py
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/browser-smoke.mjs
```

固定输入为 `scenarios/m4-river-operation.json`、`m4-river-orders.json`；HTTP 验证输出 `tactical-server/target/m4-http-run.json`、`m4-http-events.jsonl`，浏览器截图为 `m4-coordination.png`。产品运行不依赖 Node、Playwright 或 Maven wrapper。
