# M5：单次学说实验闭环

规则版本为 `m5-lab-1`。产品仍只使用原生 HTML/CSS/ES Modules/SVG；浏览器不执行战斗、机动、通信或情报规则。

## 完整浏览器演示

1. 启动服务器并连接后，在「部署战场」选择「河谷实验」。预设含混编装甲突击团、工兵、炮兵、双通信连旅部、敌方混编防线，以及首日学说和依赖图。默认将迭代上限设为 6，允许完成接敌后的撤退。
2. 可在部署面板修改地图、团连、HP、设施和通信；「情报」页可按观察者编辑已知部队、补给和通信工事 ID。输入必须引用实际存在的部署。
3. 冻结部署，启动实验并进入推演。首日蓝／红双方命令会从已存方案预填；它们尚未提交或锁定，仍可编辑。
4. 蓝方「协作」页显示 `bridge + fire → cross`。在「学说」页可修改装甲的突破失败撤退参数。双方分别提交、确认锁定后，点击「结算当日」。
5. 预设中工兵架桥、炮兵完成火力任务后，装甲收到确认再渡河接敌；未能突破时依照已知补给位置撤回 `(1,1)`。任务失败与撤退完成各有日志，不把撤退到位当成突击成功。
6. 选择结算日期，点击「回放所选日」。可播放、暂停、前后步进或拖动时间轴；回放中不可提交命令。「返回当前」恢复指挥，并保留进入回放前尚未提交的本地命令。
7. 切换师部／全知观察可比较同一历史阶段。师部视角不会提前显示后来才送达的报告；进入 N+1 的最后一帧明确标注「报告送达」。切换阵营／视角从该视角的首帧开始。
8. 按团和任务筛选指挥记录。点击 DAG 节点筛选任务日志，点击记录定位地图与团详情；「检视部队」模式点击团可查看连队报告和关联事件。团标最多两个图标，分别表示主体与显著机动瓶颈，悬停可看完整名称和服务端计算的基础速度。

历史回放显示服务端保存的完整同时间批次结果，不是按日志逐条在浏览器扣 HP。因此同一轮互射不会出现半边战损已经应用、另一边尚未应用的中间画面。普通 `BOMBARD` 的任务完成仅表示射击行动完成，不承诺敌军已被消灭。

## 保存与重开方案

在第 1 天提交双方命令后，点击「另存实验方案」。服务端检查当前日期和双方命令版本，创建一份新草稿，保存：

- 初始地图、格边、团连、设施、通信配置和初始情报；
- 双方首日命令及其学说参数；
- 旅属、战区、DAG 前置依赖与失败分支。

页面重新载入、复制草稿、导出 JSON 后再导入、冻结并重开实验都保留这些内容。已冻结版本和已经启动的实验不会被修改。输入中新增可选 `setup`、`initialKnowledge`，旧场景缺省为空，仍可导入。

另存需要双方都已提交且没有本地未提交修改；它只保存初始实验方案，不把第 2 天以后战况伪装成初始部署。若已存方案引用的团、目标或路线不再符合新部署，保存会拒绝并说明原因；可先在「情报」页清空首日方案，再编辑部署。初始情报引用的实体被删除前，也需更新对应情报。

数据仍在进程内存中。服务器重启前需导出重要场景与日运行清单；跨重启存档、批量 A/B 和多种子实验属于 M6。

## 初始情报语义

`InitialKnowledge(observerId, regimentIds, supplyIds, relayIds)` 描述场景作者明确授予某个观察者的真实初始快照，时间为 D0。不允许任意捏造坐标、HP 或不存在的实体，不自动把一名侦察团获知的情报交给师部。默认本地观察、师部已知本方部署及已勘测格边仍保留。

授予普通团的补给情报进入该团的初始记忆，可用于其学说；授予师部的情报直接进入本方初始师部视图。初始报告保留在源观察者，第一天结算进入 D2 时按通信连接上传／共享；失联则继续滞留。单纯切换视图不会共享情报。

## 回放和 API

- `GET /api/v1/presets/doctrine-lab`：完整演示预设。
- `GET /api/v1/scenarios/{id}/markers`：部署团标元数据；主体、机动瓶颈、装备形态与当前位置基础速度由服务端提供。
- `POST /api/v1/games/{id}/blueprint`：请求体为 `day`、`blueVersion`、`redVersion`，另存首日已提交方案。
- `GET /api/v1/games/{id}/days/{day}/replay?frame=0&perspective=DIVISION&side=BLUE`：返回单个历史观察帧、当前下标、可用帧数、阶段、日内时间、地图、可见报告／日志和本方计划。非法帧返回 400，未结算日期返回 404。

引擎通过纯 Java 的观察回调输出不可变快照，应用层按日期保存；不把整条时间线附在普通日归档响应中。一个回放请求只取一帧，播放串行请求，没有重复结算或修改实验状态。普通日清单与 JSONL 仍可导出、按原输入独立重放。

全知时间线包含计划开始、发生事件的完整批次、日末和 N+1 报告边界。师部时间线只保留本方实际获知的变化和报告边界，帧数／时间不会直接暴露远方不可见行动。日期与观察者切换使用对应的历史知识，不能借用当前师部已收到的新报告。

M5 增加 `OperationOutcome / SUCCEEDED / FAILED`，用于区分任务结果与后续学说行动。M5 追击、战斗、协作固定摘要另存 `scenarios/m5-*-expected.json`，历史摘要不覆盖。场景规范化编码在非空方案／初始情报时追加 `experiment-v1` 段；没有新字段的旧场景仍保持原有场景指纹。

请求执行期间显示进行中状态，地图缩放和平移、详情标签仍可操作；回放可暂停，取消的迟到响应不会覆盖当前画面。失败后提供「重新载入」入口，只重新读取服务端状态，不自动重复创建或提交请求。

## 验证

```sh
mvn -o -B -ntp spotless:apply clean verify
python3 scripts/smoke-test.py
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/browser-smoke.mjs
```

M5 专项测试覆盖初始情报授权范围／非法引用、首日方案版本检查、复制／导入／冻结重开、回放与无观察回调结算一致、历史知识隔离、回放查询无副作用、团标瓶颈，以及从浏览器编辑到回放的闭环。

HTTP 输出 `tactical-server/target/m5-lab-run.json`、`m5-replay-final.json`；浏览器输出 `m5-replay.png`，并检查 1980×1080、1920×1080、1980×960 的初始情报编辑和回放面板不溢出。开发验收工具使用 Playwright，产品不依赖 Node 或第三方前端库。
