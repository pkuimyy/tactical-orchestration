# M6：配对实验与本地归档

M6 完成 MVP 的实验对照和发布门禁。规则仍为 `m5-lab-1`，随机算法仍为 `sha256-keyed-v1`；本次没有改变战斗、机动、情报或调度公式。新增的本地存档／实验归档格式为版本 1。接口定义继续从 Java 控制器生成，不提交 OpenAPI 文件。

## 从浏览器完成对照

1. 启动 JAR，打开同源页面并输入本次会话令牌。进入顶部「实验对照」，点击「载入河谷对照」。也可在部署页冻结自己的场景，再选择「使用当前冻结版本」。
2. 输入逗号分隔的种子，例如 `1,2,3,42`。A 默认旅部保序，B 默认团独立行动；可以分别修改已有突破学说的撤退阈值。目标默认装甲突击团占领 `(4,0)`，也可不设占格目标。
3. 点击「启动配对实验」。服务端返回实验 ID，页面轮询进度。每个种子依次运行 A、B，两次都从同一个不可变冻结部署起步，不继承前一场的战后状态。运行期间可以切换到其他页查看战场。
4. 结果表每页六行，显示目标、完成天数、双方累计 HP 损失、等待／无效行动、依赖失序／任务失败。点击「详报」查看每个连的初始／最终 HP、扣血与恢复、撤退规划及日末实际位置、逐日任务状态。
5. 点击「回放」，服务器先按归档命令重放核对，再创建一个独立战局，打开 M5 历史回放。切换师部／全知观察不改变真实事件。重复打开同一次结果返回同一个战局；原批量归档不会随战局继续推演而改变。
6. 「导出完整归档」保存冻结输入、双方各日命令、学说／协同、种子、规则版本、日清单、真实日志、结果和指标。「读取归档」可恢复页面选择；服务器重启后归档仍在。
7. 可停止批量；已完成的运行保留，当前未完成运行在日边界退出且不写入半场结果。终止后可以导出或删除归档释放额度。删除不删除已经打开的独立战局。删除前界面会确认。

河谷演示的守军足以阻止装甲突破。独立行动可能因提前撞上断桥而损失更少，这不意味着其完成了突击目标。因此本页不给出万能评分，也不承诺保序方案每次都赢。

A/B 使用**同一物理部署**。INDEPENDENT 禁用旅部的任务依赖保障，但保留冻结输入中的旅部实体和通信作用。这项对照隔离任务组织的影响，不测算撤除旅部后腾出的占格／编制收益。

### 多日与自定义学说

普通控件只改蓝方 DAG 的协同模式、已有 `BREAKTHROUGH` 命令的撤退阈值。没有相应命令的自建场景不会凭空新增任务或学说。红方命令使用同一冻结方案。

普通控件的观察天数大于 1 时，第 1 天执行保存的方案，后续天提交空命令，保留引擎原有的学说记忆；未完成路线不会自动重发。需要每天继续进攻、休整或换任务时，打开「逐日命令 / 高级」，编辑 `a.days`、`b.days` 中每一天的双方命令、学说与 DAG。两份日程必须等长。后续天按当时世界验证：例如已消灭团的命令、非相邻路线会使该次运行成为 `INVALID_PLAN`，保留此前完整日结果，不伪装成成功完成。结构非法的 DAG、错误首日命令直接返回 400。

## 指标口径

| 指标 | 定义 |
|---|---|
| 占格目标 | 可选目标团首次在一个已结算日的**日末**占领目标格；完成天数是该日序号。未设目标与未达成分开显示，不以任务失败后撤退完成冒充突击成功 |
| 连级 HP | 初始与最终 HP，以及 DAMAGE 日志实际扣血总和；恢复独立列出，满足 `初始 − 扣血 + 恢复 = 最终`。不存在的团最终 HP 为 0 |
| 等待次数 | `WAITING*` 状态日志条数；是状态转换计数，不是等待时长或每一内部 tick 的数量 |
| 无效行动 | `BLOCKED`、`IMPASSABLE`、`ACTION_FAILED`、`CANCELLED` 日志条数 |
| 依赖失序 | 某节点开始执行时，未在更早 tick 成功完成的每一条前置依赖计一次；独立模式仍保留原 DAG 作为对照标准 |
| 任务失败 | 逐日命令最终失败数。DAG 使用明确任务事实；非 DAG 命令检查失败事件，后续撤退完成不覆盖失败。未完成另列 |
| 撤退去向 | 学说选择的已知补给点及规划路径，同时列出该日日末实际位置与是否到达该补给点 |
| 配对汇总 | 只纳入 A、B 均完整运行的种子，给出目标达成次数与 `B − A` 平均差。取消、未运行、非法后续计划不进入完整配对统计，不做统计显著性／普遍胜率声明 |

## HTTP 使用

正式入口无需专门 CLI。使用浏览器或任何携 Bearer Token 的 HTTP 客户端即可。`scripts/m6-smoke-test.py` 是完整可执行样例。

| 接口 | 用途 |
|---|---|
| `POST /api/v1/experiments` | 返回 202；输入 `requestId`、`revisionId`、`seeds`、`maxIterations`、A/B `name + days`、可选 `goal` |
| `GET /api/v1/experiments`、`GET /api/v1/experiments/{id}` | 查询进度、逐次摘要和完整配对的描述性差值 |
| `POST /api/v1/experiments/{id}/cancel` | 停止，保留已完成运行；重试不重新运行 |
| `DELETE /api/v1/experiments/{id}` | 删除终态归档；活动实验返回 409；已打开战局保留 |
| `GET /api/v1/experiments/{id}/export` | 完整可追溯归档，含冻结部署、请求和所有已完成结果 |
| `GET /api/v1/experiments/{id}/runs/{index}` | 单次完整结果与逐日清单；从 0 开始，顺序为种子 1 的 A/B、种子 2 的 A/B，依此类推 |
| `GET /api/v1/experiments/{id}/runs/{index}/events` | 该次所有已完成日的真实事件 JSONL |
| `POST /api/v1/experiments/{id}/runs/{index}/game` | 验证记录后打开独立战局，相同结果重试返回同一 ID |

同 `requestId` 和同参数的提交返回已有实验；同 ID 配不同参数返回 409。新一轮重复实验需要新 ID。浏览器请求失败重试会沿用原 ID。

资源边界：每组 1–16 个不重复种子、每方案 1–30 天、每日日内 1–8 次迭代，`2 × 种子数 × 天数 ≤ 256`；最多 16 组已保存实验、同时最多 2 组运行／排队，只有一个批量执行线程。沿用 64 KiB 请求限制、2–16 格地图边长、16 节点 DAG、身份与旅属校验；超过额度返回 429，超大请求返回 413。纯 Java 引擎仍只在服务端运行。

## 本地保存、重启和备份

从旧 M5 内存版本升级前，需先导出仍在旧进程中的重要场景；M6 只能自动保存本版本接收的内容，不会读取另一进程的内存。

默认目录为启动工作目录下的 `.runtime/data`，可通过 `TACTICAL_DATA_DIR` 或 `--tactical.data-dir=/absolute/path` 指定。该目录不纳入版本管理。多服务必须使用不同数据目录、端口和令牌文件；目录内的进程锁拒绝同时写入。

- 草稿、管理状态、冻结版本、战局、双方已提交／已锁定命令、已结算日与编辑记录，在写 API 成功返回前保存。
- 每次写入使用 0600 临时文件，刷新文件数据后原子替换；目录权限为 0700。场景写入失败会回滚内存变更，不返回成功。每个存档文件上限 256 MiB。
- 战局启动重载时使用原规则、原命令及种子重算历史帧，核对完整日清单和结果。损坏、不匹配或版本不兼容时启动失败，保留原文件，不静默清空。M6 不提供旧规则自动迁移。
- 批量每完成一个独立运行就写检查点。进程被强制终止后，启动从最后完整运行继续；没完成的那次从冻结输入重来。显式取消的任务不会自动恢复。
- 批量存档保存结果；打开为战局时重新核对。归档格式为可信本地数据，没有接受任意文件路径的 API。
- 停服后备份整个数据目录；在相同程序版本下恢复目录即可。JSON 导出适合审阅和携带输入／结果，目前不提供任意批量归档上传接口。需要复跑时导入导出的冻结场景，再提交其中的实验参数。
- 令牌独立于数据目录，每次启动重新生成，重启后需重新连接。运行数据及日志不保存令牌。

当前采用有上限的本地文件仓库，不提供数据库、云同步或跨规则版本迁移。使用文件系统支持原子替换和 POSIX 权限的 Linux／WSL 环境。

## 固定回归与离线发布门禁

`scenarios/m6-regression-suite.json` 固定七组场景的完整初始输入、双方日命令、种子和可读预期断言。失联和残编两组包含子场景，总计 10 个场景、16 个种子输入。`m6-regression-expected.json` 保存稳定状态与 JSONL 摘要；M2–M5 历史黄金资产仍保留。

1. 架桥渡河：完成与合法确认之后启动渡河；独立模式另用 16 个种子验证既存在保序也存在失序。
2. 炮火准备／突击：开火完成先于突击，实际造成敌军连级损伤，炮兵不凭空受反击。
3. 突破失败／撤退补给：退往已知后方补给，实际到达；另测后续休整不会冲销累计扣血。
4. 侦察 6 vs 装甲 5：固定等价路线保持速度差，没有免费接敌。
5. 2 装甲＋4 徒步步兵填线：双方实际连级战损，混编数量与装备断言。
6. 失联与 N+1：连接时 N+1 送达；同输入的断网子场景保留本地知识和滞留报告，不提前共享。
7. 单连残编阻击／驱逐：被歼灭后攻击者前进；平原和山口的存活低组织度残编也会被驱逐。

```sh
mvn -o -B -ntp spotless:apply clean verify
python3 scripts/smoke-test.py
python3 scripts/m6-smoke-test.py
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/browser-smoke.mjs
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/browser-m6.mjs
```

完整构建、离线依赖准备和启动步骤见 README。可执行 JAR 包含运行依赖、原生 Web 与预设，不依赖网络服务；测试用 Python、Node、Playwright 不是产品运行依赖。

产物均写入 `tactical-server/target/`：`m6-regression/*.jsonl` 与日结果、`m6-http-*.json`、`m6-paired-results.json`、`m6-benchmark.json`、`m6-experiments.png`。基准固定为 `m6-scale-benchmark.json` 的 24 团、30 天、2 个种子 A/B 共 120 个运行日，验证重复结果及后台 HTTP 响应，不宣称大型战役性能。
