# M2 · 一日 WEGO 与机动

规则版本 `m2-wego-1`；下表为可替换的 MVP 测试参数。HTTP 字段及路由以代码生成的
`/api/v1/openapi` 为准，本页只说明领域语义与复现方式。

## 命令与实例生命周期

实验保留不可变 `initialState`，另有独立的当前战场快照。创建后已完成天数为 0，
正在规划第 1 天。双方分别提交整批路线命令，再确认该批次版本；双方都确认后状态为
`LOCKED`，此时才能结算。成功结算保存当日结果，并进入下一天的 `PLANNING`，清空双方批次。

- 每方最多 32 条命令，每团每天最多一条；同方 orderId 唯一。路线最多 64 个相邻格，
  不含起点。空路线与未下令部队均为原地待命；空批次仍须明确提交、确认。
- 禁止跨方下令、移动城市师部、使用不存在的团或地图外／不相邻路径。
  不可通行地形允许提交，在执行时产生 `IMPASSABLE` 结果，便于解释失败原因。
- 提交携带 `day` 与 `expectedVersion`，首次版本为 0；更改批次递增版本。
  相同内容、相同请求版本的重试不再次递增；旧版本不同内容返回 409。
  确认使用已提交版本，锁定后不能更改，重复确认无副作用。
- 结算显式指定日期，服务端串行检查与更新。重复结算已完成日期返回同一份已存结果，
  不改变当前天数；未锁定、过去的命令写入、未来日期请求返回 409。
- 每局最多 60 天，达到上限为 `LIMIT_REACHED`；旧结果仍可读取或重试获取。
  实验、历史结果均在服务进程内存中，重启清空。长期保存请导出冻结输入、运行清单和事件。

## 通行与最慢连

先计算每个 HP > 0 的连在目标地形和格边上的速度，再取全团最小值；死亡连不拖慢全团。
任何有效连不可通行则全团停下。装备而非兵种名称决定基础机动；机械化／摩托化／履带侦察
在开阔地速度 6，其余同装备连速度 5；徒步侦察仍为 2。

| 装备 | 平原／城市 | 森林 | 高地 | 山地 |
|---|---:|---:|---:|---:|
| 徒步 | 2 | 2 | 1 | 1 |
| 摩托化 | 5（侦察 6） | 1 | 4（侦察 5） | 不可通行 |
| 机械化／履带 | 5（侦察 6） | 3 | 4（侦察 5） | 不可通行 |
| 牵引 | 3 | 1 | 2 | 不可通行 |

道路取消森林／高地降速，但不能使重装备穿越山地。河流格边必须有完好桥梁，
即使有道路或工兵连也不会自动架桥；工程任务属于后续里程碑。
HP 尚只决定连是否有效，组织度和战损公式在 M3 实现。

## 有限事件推进与冲突

纯 Java 引擎使用整数到达时间，一格耗时 `60 / 路段速度`，表内速度均整除 60。
每次事件迭代推进最多 15 个内部时间单位，默认 4 次；创建实验可选 1–8 次，固定进入运行清单。
因此默认开阔地徒步移动 2 格、装甲 5 格、机械化侦察 6 格。这些窗口只有计算限额含义，
不是玩家可见的侦察／移动／炮击等固定阶段。

环境起动延迟由 SHA-256 稳定键派生，为全场共享的 0–3 个时间单位；当日截止时间同步平移，
不会改变各团日机动预算。同到达时刻的任务按种子派生键排序写日志，**先收集全部意图，
再判冲突，最后一起更新位置**。随机域含种子、天数、事件种类和团 ID，算法版本为
`sha256-keyed-v1`。更换种子会改变允许的时间／日志顺序，不会赐予慢部队额外移动距离。
独立任务更复杂的行动延迟、工程依赖与通信确认留待 M4。

- 同时争夺同一格：全部参与者保持原位；没有任一方因先遍历而成为守方。
- 同时对向交换相邻格：双方保持原位，记录 `CROSSING`。
- 目标仍被占据：进入者停止，记录 `OCCUPIED`。若占据者在同一时刻可合法离开，允许跟进。
  若其离开受阻，则向后传播阻挡直到稳定，之后才应用位置变更。
- 接触与阻挡（包括友军阻挡）形成含参与团 ID 的 `CONTACT` 和 `BLOCKED` 记录；
  M2 尚不计算伤害或驱逐，也不会给任一同刻争夺方免费占格。
- 到达终点为 `COMPLETED`；时间上限内无法完成为 `DEFERRED`，停在已到达的位置。
  剩余路线不会自动跨日执行，次日须重新下令。

## 清单、日志与复现

每次结算保存冻结场景哈希、当前输入哈希、规则／随机算法版本、种子、天数、迭代上限和
规范化后的双方命令。结果包含新战场、状态哈希与事件。
状态哈希为 UTF-8 的 `day + ":" + ScenarioHash.sha256(world)` 再取 SHA-256。

JSONL 每行带 `schemaVersion: 1`，类别为 `WorldEvent` 或 `OrderTransition`，包含稳定事件 ID、
日期、迭代、时间、路段速度、团／命令关联、起终格、参与者和原因。事件 ID 不含随机实例 UUID
或系统时钟。空事件集合导出为空文件。事件/状态一致性针对相同输入和命令 ID；浏览器新编命令
会生成新 ID，要逐字节重放须使用运行清单里的命令。

固定验收资产：`scenarios/m2-recon-pursuit.json`、`m2-recon-orders.json` 和
`m2-recon-expected.json`。默认种子 42、4 次迭代，侦察从 (1,1) 到 (7,1)，
装甲从 (0,1) 到 (5,1)，没有接触。摘要变化必须检查规则变化后显式更新。

构建后执行 `python3 scripts/smoke-test.py` 可独立通过 HTTP 导入、冻结、提交、确认和运行两场实验，
比对日志与结果，并检查固定摘要。输出位于 `tactical-server/target/m2-http-run.json`
及 `m2-http-events.jsonl`。后续日期复现需要此前日期结果或从冻结输入顺序执行之前的清单。

## 浏览器操作

1. 部署页点击「追击验证」，或导入上述固定场景；冻结后选择种子与迭代上限，启动独立实验。
2. 点击实验卡片「进入推演」。选择蓝方、机械化侦察团，依次点 (2,1)…(11,1)，提交并锁定。
3. 切红方、装甲追击团，依次点 (1,1)…(10,1)，提交并锁定，点击「结算当日」。
4. 地图显示服务端返回的位置。记录分页显示，点击记录定位并查看原因／速度。
   顶部可选择历史日期、导出运行清单和 JSONL；选择历史日志不会把当前地图切换为历史回放。
5. 返回部署页仍是冻结前的独立草稿；运行位置不回写草稿。

当前是全信息机动验证视图，未实现 M4 的分层情报。没有浏览器规则引擎，客户端仅编辑路线并显示结果。
